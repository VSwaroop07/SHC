# SHC — Self-Healing Cluster: Project Walkthrough

## What Was Built

A full end-to-end **Self-Healing Kubernetes Cluster** system with:

| Component | Details |
|-----------|---------|
| ML Model | Isolation Forest, 8 features, 5 failure scenarios, 5000 training samples |
| ML Service | Python FastAPI with Pydantic validation, `/predict`, `/health`, `/info` |
| Demo-Service | Node.js + Express + WebSocket — monitor loop, healing engine, static server |
| Dashboard | Dark-mode HTML/CSS/JS with Chart.js, real-time WebSocket feed |
| Kubernetes | RBAC, Deployments, Services, resource limits, health probes |

## How to Run Locally (Demo)

### Terminal 1 — ML Service
```powershell
cd ML-Model
pip install -r requirements.txt
python train_model.py        # generates anomaly_model.pkl + scaler.pkl
uvicorn ml_service:app --host 0.0.0.0 --port 8000
```

### Terminal 2 — Demo Service + Dashboard
```powershell
cd Demo-Service
npm install
$env:ML_SERVICE_URL = "http://localhost:8000"
node index.js
```

### Browser
Open **http://localhost:3000** — that's the live dashboard.

## ML Model Details

- **Algorithm**: Isolation Forest (unsupervised anomaly detection)
- **Features (8)**: `cpu_usage`, `memory_usage`, `request_rate`, `latency`, `pod_restarts`, `disk_io`, `network_errors`, `error_rate`
- **Failure Scenarios Trained**: CPU Spike, Memory Exhaustion (OOM), Disk I/O Saturation, Network Degradation, Crash Loop
- **Contamination**: 10% (expects ~10% of traffic to be anomalous)
- **Estimators**: 200 trees

## Demo Flow (For Presentation)

1. Open the dashboard — show **NORMAL** state with live charts
2. Click **"⚡ Simulate Node Stress"**
3. Watch within ~30 seconds:
   - Status badge switches **NORMAL → DETECTING → CONFIRMED**
   - Node cards change from Healthy → Degraded → Critical
   - Metric bars turn red/amber
   - Healing event appears in the log table
4. Click **"↺ Reset to Normal"** — everything recovers
5. Explain the automatic 60-second scenario rotation (CPU Spike → OOM → Disk I/O → Network → Crash Loop)
